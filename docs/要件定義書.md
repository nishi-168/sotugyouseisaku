# イベント管理アプリ 要件定義書

## 1. アプリ概要

イベント主催者と参加者をつなげるWebアプリケーション。小規模な飲み会からスタジアムレベルのライブまで、幅広い規模のイベントを募集・参加できることを目指す。

## 2. 開発背景・目的

IT研修の卒業制作として開発。研修期間中に習得した技術(TypeScript、React、Next.js、Prisma、PostgreSQL)を用いて、CRUD操作を中心としたWebアプリケーションを実装することを目的とする。

## 3-1. 使用技術

- 言語:TypeScript
- フロントエンド:React、Next.js(App Router)
- ORM:Prisma
- データベース:PostgreSQL
- 入力検証:yup
- スタイリング:Tailwind CSS

## ディレクトリ構成の考え方

- **`src/app/`配下**:Next.jsのApp Routerの規約に従い、フォルダ構造がそのままURLのパスに対応する。各フォルダの`page.tsx`が画面表示、`actions.ts`がそのフォルダに関連するServer Action(フォーム送信時の処理)を担う。
- **`[id]`フォルダ**:動的ルーティング用のフォルダ。`participant/[id]`であれば`/participant/1`、`/participant/2`のように、IDごとに異なるイベントを表示する。
- **`page.tsx`と`actions.ts`を同じフォルダに置いている理由**:「その画面で使う処理」を近い場所にまとめることで、関連するコードを探しやすくするため。例えば`organizer/new/`フォルダには、新規作成フォーム(`page.tsx`)と作成処理(`actions.ts`)がセットで置かれている。
- **`src/lib/`**:特定の画面に属さない、複数のファイルから共通して使う機能(DB接続、ランク判定ロジック)をまとめる場所。
- **`src/components/`**:複数の画面をまたいで使う可能性がある、または`"use client"`が必要なUI部品を置く場所。今回は`EventListWithFilter`のみ該当する。
- **`src/generated/`**:Prismaが自動生成するコードの出力先。手動で編集することはない。

## 命名規則

- ページの実体は必ず`page.tsx`という固定名にする(Next.jsのApp Routerの規約)
- Server Actionをまとめたファイルは`actions.ts`に統一している
- コンポーネントファイルは、内容が分かる名前(パスカルケース)を付ける(例:`EventListWithFilter.tsx`)
## 4. 機能要件

### 4.1 ユーザー識別機能

- パスワードによるログイン認証は実装しない(研修範囲外のため)
- 新規ユーザーは名前・生年月日・電話番号・メールアドレスを入力して登録できる
- 既存ユーザーは、メールアドレスを入力して自分を検索し、選択することで本人として識別される(疑似ログイン方式)
- 識別されたユーザー情報はブラウザのCookieに保持し、以降の操作で本人として扱う
- ログアウト機能により、Cookieの識別情報を削除できる
- イベント一覧の閲覧など、本人確認を必要としない操作はログインなしでも可能とする

### 4.2 アカウント情報管理機能

- ログイン中のユーザーは、自分の登録情報(名前・生年月日・電話番号・メールアドレス)を閲覧・編集できる
- メールアドレスを変更する場合、他のユーザーが使用していないか確認する
- 自分が過去に参加登録したイベントの履歴を確認できる
- 主催回数・参加回数に応じたランク(ブロンズ/シルバー/ゴールド/ダイヤモンド/レジェンド)を表示する

### 4.3 イベント投稿機能(主催者)

- 主催者はイベント名・場所・開催日時・募集人数・詳細・カテゴリ・申込期限を入力してイベントを投稿できる
- カテゴリは、あらかじめ登録された一覧からプルダウンで選択する
- 申込期限は開催日時より前でなければならない
- 投稿すると、投稿者の主催回数が加算される
- 投稿したイベントは、事後に編集・中止ができる

### 4.4 主催イベント管理機能

- 主催者は、自分が主催しているイベントの一覧(開催中・中止済みを含む)を確認できる
- 開催中のイベントは編集・中止操作が可能で、中止済みのイベントは履歴として閲覧のみ可能とする
- イベントの中止は、レコードを削除するのではなく、状態(ステータス)を変更する形で行い、中止理由を任意で残すことができる

### 4.5 イベント一覧・検索機能(参加者)

- 開催中の全イベントを一覧表示する
- カテゴリによる絞り込みができる(画面遷移を伴わず、その場で一覧が切り替わる)
- 申込期限が近いイベントを、ホーム画面の上部にピックアップ表示する(最大4件)
- 直近に作成されたイベントを、ホーム画面の上部にピックアップ表示する(最大3件)
- 中止されたイベントは、参加者向けの一覧・ピックアップには表示しない

### 4.6 イベント詳細・参加申込み機能

- イベントの詳細情報(場所・日時・募集人数・詳細・カテゴリ・申込期限・現在の参加人数)を確認できる
- 参加ボタンから参加申込みができる。ただし以下の場合は参加できない
  - ログインしていない場合(ログイン画面に案内する)
  - 自分が主催するイベントである場合
  - 定員に達している場合
  - 既に参加登録済みである場合
- 参加人数はEventテーブルに専用カラムを持たせず、参加記録(Participation)の件数から算出する
- イベントの主催者名から、その主催者の公開ページに遷移できる
- 中止されたイベントの詳細ページには、中止済みである旨と中止理由を表示する

### 4.7 主催者公開ページ機能

- 誰でも(ログインなしでも)、ある主催者の公開情報を閲覧できる
- 表示内容は、名前・主催ランク・現在募集中のイベント一覧に限定し、個人情報(電話番号・メールアドレス・生年月日)は表示しない
- 編集機能は持たず、閲覧専用とする

## 5. 非機能要件・設計方針

- 参加人数や主催回数などの集計値は、データから都度算出する
- データの整合性が求められる複数の更新処理(参加登録と参加回数の加算など)は、トランザクションを用いて一括で実行する
- 入力値の検証は、ブラウザ標準の検証とサーバー側の検証(yup)の二段階で行う
- イベントの削除は物理削除ではなく、ステータス管理による論理削除とし、履歴を保持する

## 6. スコープ外の機能

- パスワードによるログイン認証
- 募集方式における抽選機能の実運用(先着順のみ実運用とし、抽選は今後の拡張候補とする)
- メール等による通知機能
- イベントへの画像添付機能

## 7. 想定利用シーン

- 小規模な飲み会や勉強会など、少人数で身内的に募集するイベント
- スポーツサークルや趣味の集まりなど、中規模の定期的なイベント
- ライブやコンサートなど、大規模な募集を伴うイベント
