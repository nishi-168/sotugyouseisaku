# イベント管理アプリ 設計書

## 1. テーブル一覧

| テーブル名 | 概要 |
|---|---|
| User | 利用者情報。主催者・参加者の区別なく、同一ユーザーが両方の役割を担う |
| Event | イベント情報 |
| Participation | イベントへの参加登録情報(User と Event の中間テーブル) |
| Category | イベントのカテゴリマスタ |

## 2. テーブル定義

### 2.1 User(ユーザー)

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | Int | PK, auto increment | ユーザーID |
| userName | String | NOT NULL | 名前 |
| birthDate | DateTime | NOT NULL | 生年月日 |
| phoneNumber | String | NOT NULL | 電話番号 |
| email | String | NOT NULL, UNIQUE | メールアドレス。疑似ログインの検索キーとしても使用 |
| participationCount | Int | NOT NULL, default 0 | 参加回数(非正規化。ランク判定に使用) |
| hostedCount | Int | NOT NULL, default 0 | 主催回数(非正規化。ランク判定に使用) |
| createdAt | DateTime | NOT NULL, default now | 登録日時 |

**設計メモ**
- パスワードによる認証は行わない。ログイン機能を研修で扱っていないため、メールアドレスによる検索・選択で本人を識別する疑似ログイン方式を採用した。
- 主催者・参加者を分けるroleカラムやテーブルは設けていない。同一ユーザーが両方の立場になれる要件のため、Event側・Participation側からそれぞれ別の目的で参照する構成とした。
- participationCount / hostedCountは、参加登録・イベント作成のたびにインクリメントする非正規化データ。ランク自体(ブロンズ/シルバー/ゴールド)はDBに保存せず、表示時にこの数値から算出する。

### 2.2 Event(イベント)

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | Int | PK, auto increment | イベントID |
| name | String | NOT NULL | イベント名 |
| location | String | NOT NULL | 場所 |
| eventDatetime | DateTime | NOT NULL | 開催日時 |
| capacity | Int | NOT NULL | 募集人数 |
| description | String | NULL可 | 詳細(任意項目) |
| categoryId | Int | FK → Category.id | カテゴリ |
| deadline | DateTime | NOT NULL | 申込期限 |
| organizerId | Int | FK → User.id | 主催者 |
| recruitmentType | String | NOT NULL, default "first_come" | 募集方式("first_come" / "lottery")。現バージョンはfirst_comeのみ運用 |
| status | String | NOT NULL, default "active" | イベントの状態("active" / "cancelled") |
| cancelReason | String | NULL可 | 中止理由(中止時、任意入力) |
| createdAt | DateTime | NOT NULL, default now | 登録日時 |
| updatedAt | DateTime | NOT NULL, auto update | 更新日時 |

**設計メモ**
- 現在の参加人数はカラムを持たず、Participationの件数から都度算出する(`_count`)。更新漏れによるデータのズレを防ぐため。
- カテゴリは表記ゆれ防止・検索精度確保のため、文字列ではなくCategoryテーブルへの外部キーとした。
- recruitmentType・statusは選択肢が少なく、主催者側で自由に増減させるものではないため、あえて別テーブル化せず文字列(Enum的な扱い)としている。
- イベントの中止は物理削除ではなく、statusを"cancelled"に更新する論理削除方式とした。履歴を残しつつ、参加者向け一覧からは除外するため。

### 2.3 Participation(参加情報)

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | Int | PK, auto increment | 参加ID |
| userId | Int | FK → User.id | 参加ユーザーID |
| eventId | Int | FK → Event.id | 対象イベントID |
| appliedAt | DateTime | NOT NULL, default now | 申込日時 |
| status | String | NOT NULL, default "applied" | 参加ステータス("applied"等。抽選機能導入時は"confirmed"/"rejected"等を想定) |

**設計メモ**
- User と Event の多対多の関係を表現する中間テーブル。
- 同一ユーザー・同一イベントの組み合わせでの重複登録は、アプリケーション側(参加処理実行時の事前検索)で防止している。

### 2.4 Category(カテゴリ)

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | Int | PK, auto increment | カテゴリID |
| name | String | NOT NULL, UNIQUE | カテゴリ名 |

**設計メモ**
- 主催者はイベント登録・編集時に、このテーブルの内容からプルダウンで選択する。
- カテゴリの追加はテーブルにレコードを追加するだけで反映され、コード変更を必要としない。

## 3. テーブル間リレーション

| No | 関連元 | 関連先 | 種類 | 外部キー | 意味 |
|---|---|---|---|---|---|
| 1 | User | Event | 1 : N | Event.organizerId → User.id | 1人のユーザーは複数のイベントを主催できる |
| 2 | User | Participation | 1 : N | Participation.userId → User.id | 1人のユーザーは複数のイベントに参加申込できる |
| 3 | Event | Participation | 1 : N | Participation.eventId → Event.id | 1つのイベントには複数の参加申込が存在できる |
| 4 | Category | Event | 1 : N | Event.categoryId → Category.id | 1つのカテゴリは複数のイベントに設定される |

**間接的な多対多の関連**

| 関連元 | 関連先 | 種類 | 経由 | 意味 |
|---|---|---|---|---|
| User | Event | N : N | Participation | 1人のユーザーは複数のイベントに参加でき、1つのイベントには複数のユーザーが参加できる |

**補足:同一のUser-Event間に生まれる2つの独立した関連について**

UserからEventへは、「主催者として」(organizerId経由)と「参加者として」(Participation経由)という、2つの独立した関連が存在する。これはループ構造に見えるが、それぞれ別のカラム・別のテーブルで管理されており、片方が他方に影響することはない。同一ユーザーが自分のイベントに参加登録することは、アプリケーション側のロジックで明示的に禁止している(データ構造上の制約ではなく、業務ルールとしての制約)。

## 4. 画面遷移・機能とテーブルの対応(抜粋)

| 画面 | 主に使用するテーブル | 備考 |
|---|---|---|
| ログイン(疑似) | User | emailで検索、Cookieに userId を保存 |
| 新規登録 | User | 登録と同時にCookieへ保存(自動ログイン) |
| イベント一覧・検索 | Event, Category | statusとcategoryIdで絞り込み |
| イベント詳細・参加申込み | Event, Participation, User | 定員・主催者・重複のチェックを実施 |
| イベント新規作成・編集 | Event, Category | 主催者本人チェックを実施(編集時) |
| イベント中止 | Event | statusとcancelReasonを更新(論理削除) |
| アカウント情報 | User, Participation | 参加履歴はParticipationを起点に取得 |
| 主催者公開ページ | User, Event | 個人情報を含まない、閲覧専用の表示 |
